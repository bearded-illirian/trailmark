## Какую проблему решает

Агент кинулся писать код без плана — и потерял половину деталей. Тесты забыты, миграция БД пропущена, коммит-сообщение неконкретное. Через час пользователь видит код не там и не такой как ожидал.

Без режима работы — пользователь не знает: агент сделает всё разом и принесёт результат, или после каждого шага будет ждать «го»? Несовместимые ожидания → разочарование на обеих сторонах.

## Как работает

Перед любым действием (документ, код, рефактор, миграция, тесты, git-операция) — таблица 7-15 строк: что конкретно делаем на каждом шаге. Implementation-шаги только, никаких «изучить X» (это flow-first).

После таблицы — выбор режима: автопилот (всё разом, отчёт по ходу) / пошаговый (после каждого шага «го») / гибридный (до шага N автопилот, потом стоп). Пользователь явно выбирает — без догадок.

После выполнения — обязательный `report.md` с блоком «Что важное по ходу» (отклонения, неочевидные находки) и блоком «Дальше» (конкретный следующий шаг).

## Результат работы

План — единый источник правды что происходит. Если агент отклонился — это видно в отчёте. Если расширил скоп — зафиксировано. Если пропустил шаг — пользователь увидит сразу.

Режим работы согласован — пользователь не ждёт когда агент уже мчится, агент не стоит когда пользователь готов отпустить.

## С какими скиллами работает

| Скилл | Зачем |
|---|---|
| library-first | Таблица LOC — основа для шагов плана. Атомы из library-first → шаги plan-first |
| ship-first | После выполнения всех шагов плана — финал через ship-first (отчёт, деплой, закрытие) |
| arch-map | После plan-first для go-fast/go-pipe — привязка артефакта к слою архитектуры |
