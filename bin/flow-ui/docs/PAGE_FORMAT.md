# Формат собранной страницы

**Версия документа:** 1.0 · 2026-08-19
**Задачи:** 698 (рендерер и каталог блоков) · 701 (сборщик и связь с исходником)

Документ описывает файл `*.page.json` — вторую проекцию документа в Экстранете.
Первая проекция — обычный `.md`, он остаётся источником и правится руками.
Собранная страница производна: её создаёт сборщик, а портал рисует своими
компонентами.

---

## 1. Правило имени и связь с исходником

Файл страницы называется `{basename}.page.json` и лежит рядом с `{basename}.md`.

```
Саммари встречи 19.08.md            ← источник, виден в дереве
Саммари встречи 19.08.page.json     ← страница, в дереве НЕ показывается
```

Портал ищет страницу по имени исходника: убирает `.md`, добавляет `.page.json`.
Никакого реестра соответствий и никаких полей в базе — связь задаётся именем.

`.page.json` — служебный файл. В дереве он скрыт, открывается только как
проекция своего `.md`.

---

## 2. Корневые поля

```json
{
  "version": 1,
  "built_at": "2026-08-19T18:42:10+03:00",
  "source_name": "Саммари встречи 19.08.md",
  "source_hash": "9f2c…",
  "blocks": [ … ]
}
```

| Поле | Тип | Обязательно | Смысл |
|---|---|:-:|---|
| `version` | число | да | Версия формата. Сейчас `1` |
| `built_at` | строка | да | Время сборки, ISO 8601 с зоной |
| `source_name` | строка | да | Имя исходного `.md` на момент сборки |
| `source_hash` | строка | да | Отпечаток исходника, см. § 3 |
| `blocks` | массив | да | Список блоков, см. § 4 |

Поля вне списка игнорируются рендерером. Добавлять свои можно, но портал
их не увидит.

---

## 3. Алгоритм отпечатка

`source_hash` = **SHA-256** от байтов исходного файла в кодировке UTF-8,
записанный шестнадцатеричной строкой в нижнем регистре, без префиксов.

```
sha256(bytes_of_source_md) → "9f2c8a1b…"
```

Считается от **всего файла целиком**, включая переводы строк. Нормализация
переносов, обрезка пробелов и любые преобразования запрещены — иначе сборщик
и портал получат разные значения и пометка об устаревании будет ложной.

Портал сравнивает `source_hash` из страницы с отпечатком текущего `.md`.
Не совпало — страница собрана раньше правок, показывается с пометкой.

Отпечаток выбран вместо времени изменения сознательно: пересохранение файла
без правок сдвигает время, но не меняет отпечаток. Обоснование — `decision-01.md`
задачи 701.

## 4. Каталог блоков

Каждый элемент `blocks` — объект с обязательным полем `type`. Остальные поля
зависят от типа. Незаполненный необязательный слот просто не отрисуется.

| Тип | Слоты | Обязательные | Что рисует |
|---|---|---|---|
| `hero` | `kicker`, `title`, `lead`, `chips[]` | `title` | Шапка документа |
| `section` | `eyebrow`, `title` | `title` | Заголовок раздела с надзаголовком |
| `meta` | `items[{label, value}]` | `items` | Плашки «поле → значение» под шапкой |
| `text` | `paragraphs[]` или `text` | одно из двух | Абзацы |
| `cards` | `items[{title, body}]` | `items`, `title` в каждом | Карточки фактов в ряд. `body` — строка или список строк |
| `kpi` | `items[{value, label}]` | `items`, `value` в каждом | Числовые показатели |
| `criteria` | `items[{name, why}]` | `items`, `name` в каждом | Пары «критерий → обоснование» |
| `zones` | `zones[{tag, name, where, steps[], notes[], link}]` | `zones` | Блоки процесса со связками |
| `stages` | `items[{tag, when, rows[{label, value}]}]` | `items` | Этапы |
| `steps` | `items[{title, body}]` | `items`, `title` в каждом | Пронумерованные шаги |
| `callout` | `kind`, `label`, `body` | `body` | Врезка. `kind`: пусто, `warn`, `danger` |
| `quote` | `text`, `author` | `text` | Цитата |
| `image` | `src`, `alt`, `caption` | `src` | Картинка с подписью |
| `files` | `items[{name, meta}]` | `items`, `name` в каждом | Вложения и ссылки |
| `table` | `title`, `head[]`, `rows[[]]`, `caption` | `rows` | Таблица с прокруткой |
| `next` | `label`, `when`, `body` | `when` | Закрывающий блок «что дальше» |
| `divider` | — | — | Разделитель |

Источник правды по слотам — реестр `RENDERERS` в `app/static/doc-blocks.js`.

## 5. Недоверенный источник

Файл страницы приходит из хранилища тенанта и **не является доверенным
источником разметки**.

- Все текстовые значения кладутся в DOM через `textContent`
- Единственное исключение — `src` в блоке `image`, он идёт в атрибут
- Разметка внутри слотов не поддерживается: теги отрисуются как текст
- Ссылки внутри текста тоже не поддерживаются — для ссылок есть блок `files`

Ограничение намеренное. Сборщик — автомат, и возможность внедрить разметку
в портал клиента через сгенерированный файл недопустима.

---

## 6. Поведение при отказах

| Ситуация | Что происходит |
|---|---|
| Неизвестный тип блока | Жёлтая врезка «тип не поддерживается этой версией портала». Остальные блоки рисуются |
| Исключение внутри блока | Красная врезка с текстом ошибки. Остальные блоки рисуются |
| `blocks` пуст или отсутствует | Сообщение «страница пуста — в файле нет блоков» |
| Файл не парсится как JSON | Портал показывает ошибку разбора и не пытается рисовать |

Принцип: **отказ одного блока не роняет страницу**. Читатель видит проблему
на месте сбоя, а не пустой экран.

---

## 7. Старшинство и версионирование

**При расхождении спецификации и кода верен код** — реестр `RENDERERS`
в `app/static/doc-blocks.js`. Спецификация правится следом.

Поле `version` сейчас **информационное**: рендерер его не проверяет и не
переключает поведение. Оно заложено на будущее — когда набор блоков начнёт
меняться несовместимо. Сборщик обязан его писать, портал обязан игнорировать.

Добавление нового типа блока не ломает старые страницы и версию не повышает.
Повышение версии потребуется только при изменении смысла существующих слотов.
