Вторая предметная встреча. На первой обсуждали идею единого шаблона, из которого
формируются утверждённые формы. После неё поступило возражение: не хотим зависеть

Задача встречи — показать устройство решения и согласовать этапность.

> [!ВАЖНО] Возражение снято переформулировкой в два критерия: экономическая
> целесообразность и зоны ответственности. Оба зафиксированы как основание решения.

## Ключевые тезисы

1. **Продукт делаем устанавливаемым.** Программа работает на компьютере пользователя, служебный сервер нужен только для лицензий и обновлений. Пиковая нагрузка приходится на последние дни апреля, держать мощности круглый год невыгодно.
2. **Масштаб больше ожидаемого.** Триста организаций, от пятисот до тысячи мероприятий на каждую. Пилот на пяти-пятнадцати из числа тех, с кем давно работают.
3. **Конфиденциальность как условие архитектуры.** Если организация покупает только программу, содержание её работы не должно быть видно. Реестр и проверка применимы лишь к клиентам с сопровождением.
4. **Замечания приходят текстом в свободной форме.** Единого формата нет, каждый регион пишет по-своему. Основные претензии касаются первичных данных, а не самих форм.
5. **Первый этап определён заказчиком.** Разложить корректный исходник по формам без всяких проверок. Первый объект — перечень мероприятий, он присутствует почти в каждой форме.

> [!ВНИМАНИЕ] Основание для паспортов проектов в переданных приказах отсутствует.
> Паспорта составляют больше половины комплекта, поэтому вопрос первый по важности.
