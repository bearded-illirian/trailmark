# Формат документа кабинета

Документ кабинета — страница, которую клиент менторинга открывает в своём портале:
домашка, обратная связь, тезисы встречи, методический документ, обложка.

Сосед этого формата — `PAGE_FORMAT.md`. Там описан документ, собранный в блоки
и отрисованный витриной. Здесь — документ, отрисованный внутри песочного фрейма.
Разница не в оформлении, а в договоре о доверии: блоки вставляются в страницу
портала и потому не могут нести разметку и ссылки; документ кабинета живёт
в изолированном фрейме и потому может.

Выбор между ними закреплён решением 19 задачи 706: кабинету нужны ссылки на задачи
и запросы к порталу, у блоков их нет по замыслу.

---

## 1. Правило имени и связь с исходником

Исходник — `{basename}.md`, обычный markdown с шапкой полей. Сборка — `{basename}.html`.

Исходник читается и правится руками. Оформление в него не попадает: вёрстку даёт
шаблон формы, стиль даёт портал (см. § 7).

---

## 2. Корневые поля

Шапка исходника — YAML перед текстом.

| Поле | Тип | Обяз. | Смысл |
|---|---|:-:|---|
| `type` | строка | да | Тип документа, см. § 3 |
| `title` | строка | да | Заголовок документа |
| `kicker` | строка | нет | Надзаголовок над заголовком: дата, номер недели |
| `lead` | строка | нет | Абзац под заголовком |
| `portal` | строка | нет | Код кабинета, если документ адресный |
| `updated` | строка | нет | Дата в тексте документа, не время сборки |

В собранный файл сборщик дописывает служебное:

| Поле | Смысл |
|---|---|
| `version` | Версия формата. Сейчас `1` |
| `built_at` | Время сборки, ISO 8601 с зоной |
| `source_name` | Имя исходного `.md` на момент сборки |
| `source_hash` | Отпечаток исходника — SHA-256 от байтов UTF-8, hex нижним регистром |

Отпечаток нужен затем же, зачем соседу: открыв страницу через месяц, видно,
собрана ли она из текущего исходника или отстала.

---

## 3. Три формы

Форм три, а не пять. Форма — это структура; тип документа — это её применение.

| Тип | Форма | Где применяется |
|---|---|---|
| `cover` | обложка | Стартовый экран кабинета, один на кабинет |
| `homework` | разбор | Домашка с пунктами и задачами |
| `feedback` | разбор | Обратная связь по работе клиента |
| `theses` | разбор | Тезисы встречи |
| `method` | методический | «Как устроен конвейер», «О проекте», «Инфраструктура» |

**Домашка не отдельная форма.** От обратной связи она отличается одним признаком:
её раздел несёт ключ панели и ссылку на задачу. Это свойство раздела, а не тип
документа. Заводить под это четвёртую форму значит завести две почти одинаковые
сущности, которые начнут расходиться.

**`theses` выведен по смыслу, а не из образца.** Документа такого типа в кабинете
на момент написания контракта не было. Если при первом применении форма не ляжет —
править здесь, а не изобретать на месте.

---

## 4. Каталог секций

Имена узлов взяты из четырёх готовых страниц кабинета — они уже устоялись.

| Секция | Поля | Обязательные | Смысл |
|---|---|---|---|
| `head` | `kicker`, `title`, `lead` | `title` | Шапка документа |
| `tiles` | `items[{value, label, tone}]` | `items` | Плитки-показатели под шапкой. `tone`: пусто, `alarm` |
| `section` | `title`, `body`, `key`, `task` | `title` | Раздел. `key` — стабильный ключ панели, `task` — ссылка на задачу |
| `rows` | `items[{label, value, tone}]` | `items` | Пары «поле → значение». `tone`: пусто, `pending` |
| `note` | `label`, `body`, `tone` | `body` | Врезка. `tone`: пусто, `pending` |
| `list` | `items[]` | `items` | Простой список |
| `quote` | `text`, `author` | `text` | Цитата клиента его словами. Своя секция, не врезка |
| `verdicts` | `head[]`, `rows[]` | `rows` | Таблица со столбцами. Ячейка вердикта становится пилюлей |
| `findings` | `items[{title, body}]` | `items` | Карточки находок. Номер рисует сборщик |
| `steps` | `items[{when, title, marks[]}]` | `items` | Слоты «шаг → время → готово» |
| `counters` | `items[{label, done, total}]` | `items` | Полосы выполнения. Ноль — тоже состояние, засечку рисует стиль |
| `compare` | `caps[2]`, `cols[2]` | `cols` | Сравнение двумя колонками. Вторая выделяется |
| `next` | `title`, `body`, `items[]` | `title` | Закрывающий блок «что дальше». Последний в документе |
| `toc` | — | — | Оглавление с якорями. Собирается сборщиком из заголовков разделов |
| `route` | `items[{n, step, where}]` | `items` | Маршрут «с чего начать». Только в обложке |
| `foot` | `body` | `body` | Подвал |

Секция `section` с заполненным `key` — это панель: из неё сборщик задач в блоке 105
заводит задачу кабинета, а ссылка внутри неё ведёт в эту задачу.

## 5. Чем пишется в исходнике

Каталог § 4 говорит, **что** есть в документе. Этот раздел говорит, **чем** оно
пишется. Раньше его не было, и это дважды стоило разрыва между контрактом
и сборщиком: контракт назвал поле `key`, а как его написать — не сказал, и скилл
задач искал разделы, которых сборщик не выдавал. Второй раз то же с плитками.

**Секция объявляется абзацем-маркером `[!имя]` перед своим блоком.** Приём взят
у врезок — там он уже работает, и второго синтаксиса учить не приходится. Тело
может стоять в том же абзаце, что и маркер: разбор склеивает идущие подряд
строки в один узел.

**Неизвестное имя секции — отказ собрать.** Молча пропустить значит потерять
содержание (§ 8).

**Маркеры разбирает только проекция `frame`.** Проекция `blocks` собирает те же
исходники по своему контракту `PAGE_FORMAT.md` и маркеров не знает — документ
кабинета собирается проекцией `frame`.

| Секция | Чем пишется |
|---|---|
| `head` | Шапка файла: `type`, `title`, `kicker`, `lead` |
| `section` | `## Заголовок` — заголовок второго уровня. Третьего уровня и глубже нет: `###` — отказ собрать, а не тихий пропуск |
| панель | `## Заголовок {#ключ}` — тот же заголовок с ключом в фигурных скобках |
| `list` | Обычный список. Маркера не нужно |
| `rows` | Таблица из двух колонок. Маркера не нужно. Шапки у неё нет — первая строка тоже пара |
| `quote` | `> текст цитаты`. Автор — через тире в конце: `> …и всё. — Встреча 27 августа` |
| `note` | `[!важно]` и текст. Годится любое имя врезки: `важно`, `внимание`, `осторожно`, `опасно`, `заметка`, `подсказка` |
| `note` ожидания | `[!ещё не сделано]` и текст |
| `tiles` | `[!плитки]` и список `значение — подпись`. Тревожная плитка — пункт начинается с `!` |
| `counters` | `[!полосы]` и список `подпись — 4 из 11`. Ширину заливки считает сборщик, ноль остаётся нулём |
| `verdicts` | `[!вердикты]` и таблица. Первая строка — шапка. Ячейка `сделано` / `наполовину` / `не сделано` становится пилюлей, прочее остаётся текстом |
| `findings` | `[!находки]` и нумерованный список, каждый пункт с жирного заголовка. Номера рисует сборщик |
| `steps` | `[!шаги]` и таблица `время \| шаг \| отметки`. Отметки через `;`, каждая как `метка: текст`; метка `готово` красится |
| `compare` | `[!сравнение]` и таблица из двух колонок. Шапка становится подписями колонок, вторая колонка выделяется |
| `next` | `[!что дальше]` и заголовок, следом абзац и список |
| `toc` | `[!оглавление]`. Содержания за собой не тянет — собирается из заголовков разделов. Номера пунктов рисует стиль, в разметке их нет |
| `foot` | `[!подвал]` и текст |

**Что можно писать внутри текста.** В абзацах, пунктах списков, врезках,
цитате и колонках сравнения работает обычная инлайновая разметка markdown:
`**жирное**`, `*курсив*`, `` `код` `` и ссылки `[текст](адрес)`.

Адрес ссылки принимается только в четырёх формах § 6 плюс `http://` и `https://`.
Всё прочее — включая `javascript:` и `data:` — остаётся **текстом**, а не
становится ссылкой: документ приходит из хранилища тенанта и доверенным
источником разметки не является. Это тот же довод, по которому у проекции
блоков ссылок нет вовсе.

В **заголовках разделов** разметка не работает и работать не будет: из заголовка
вынимается ключ панели и строится якорь оглавления, и теги внутри сломали бы оба.

**Якорь раздела.** Сборщик ставит `id` каждому разделу: из ключа панели, когда он
есть, и из порядкового номера, когда нет. Порядковый номер один не годится —
ссылка на якорь уже ушла клиенту, а раздел переставили, и якорь показывает
на чужой текст.

## 6. Ссылки

| Форма | Куда ведёт | Кто обрабатывает |
|---|---|---|
| `#task/{ключ}` | Задача кабинета по стабильному ключу панели | Портал, поиск по `panel_key` |
| `#task/{номер}` | Задача кабинета по номеру | Портал, поиск по `id`. Форма старая, остаётся навсегда |
| `#ep/{номер}` | Другой материал кабинета | Портал открывает документ |
| Внешний адрес | Как есть | Новая вкладка, `noopener` ставится порталом |

Ключ предпочтительнее номера: номер свой в каждом кабинете, ключ один на всех —
поэтому документ с ключами можно выдать нескольким клиентам, а с номерами нельзя.

---

## 7. Стиль

**Собранный документ не несёт стилей.** Общий стиль кабинета впрыскивает портал
в оболочку фрейма — `kabinet-page-style.js`, задача 721, блок 101.

Собственный `<style>` в документе допустим только как временное состояние
непереведённых материалов: он идёт после впрыснутого и перекрывает его. Новые
документы своих стилей не несут.

Нужен новый визуальный элемент — он добавляется в общий стиль и в каталог секций,
а не в отдельную страницу. Иначе у двухсот кабинетов будет двести вёрсток.

---

## 8. Поведение при отказах

| Ситуация | Что делает сборщик |
|---|---|
| Нет `type` | Отказ: тип определяет форму, угадывать нельзя |
| `type` не из списка § 3 | Отказ со списком известных типов |
| Нет `title` | Отказ: документ без заголовка неотличим от обрывка |
| Секция не из каталога § 4 | Отказ с именем секции — молча пропустить значит потерять содержание |
| `section` с `task`, но без `key` | Предупреждение: ссылка на задачу без ключа привязывает документ к одному кабинету |
| Обратная кавычка в тексте | Экранируется. Незакрытая шаблонная строка уронила бы страницу |

Отказ — это отказ собрать, а не собрать наполовину. Наполовину собранный документ
в кабинете клиента хуже, чем несобранный.

---

## 9. Старшинство

Контракт старше шаблонов. Расходятся — прав контракт, шаблон правится.

Меняется контракт — растёт `version` в § 2, и в этом файле появляется строка
о том, что изменилось и в какой задаче.

| Версия | Что появилось | Задача |
|---|---|---|
| 1 | Первая редакция: корневые поля, три формы, каталог секций, ссылки, стиль, отказы | 721, блок 103 |
| 2 | Восемь секций разбора в каталоге, раздел «Чем пишется в исходнике», якоря разделов | 721, блок 303 |
