# Часто задаваемые вопросы

## Зачем ещё один AI-фреймворк?

Большинство AI-кодинга не оставляет следа. Решения испаряются, как только закрылась сессия. Ревьюер не может проверить логику. Регрессию невозможно привязать к конкретному изменению. Новая сессия начинается с нуля.

Trailmark чинит это на уровне протокола: каждый шаг каждого скилла пишет настоящий файл, который регистрируется в `routing.db`. Если шаг не создал артефакт — значит его не было. Полная аргументация в [README](./README.ru.md#почему-artifact-first).

## Чем отличается от LangChain / CrewAI?

LangChain и CrewAI поставляют Python-рантайм плюс agent-граф, под который ты пишешь код. Артефакты — если они вообще есть — ad-hoc: callback, log-строка, что твоя обвязка захватит. Централизованного реестра нет.

Trailmark поставляет скиллы (обычный markdown), инструменты (bash) и реестр (SQLite). Никакого рантайма. Никакого SDK. Каждый шаг обязан по контракту создать отслеживаемый файл. Разные инструменты для разных задач — детали в [таблице сравнения](./README.ru.md#как-мы-сравниваемся).

## Как сравнивается с прескриптивными documentation-first фреймворками?

Прескриптивные фреймворки поставляют документацию — роли, правила, best practices, чеклисты — которую ты применяешь руками к своему коду. Trailmark поставляет исполняемые скиллы, в которых дисциплина уже закодирована. Прескриптивные фреймворки подходят когда ты формализуешь процесс команды; Trailmark подходит когда нужна дисциплина без организации, которая будет её поддерживать.

## Как Trailmark влияет на API-косты?

**Типичная стоимость блока: $0.15-2. Неделя ежедневной работы: $5-10. В 5-10 раз дешевле agent-heavy фреймворков за ту же работу.**

Три механизма экономии:

1. **Все скиллы работают в твоём основном Claude-контексте.** Никаких subagent-раздутий, которые загружают 30-40к токенов на каждый вызов. Agent-heavy фреймворки с 5 обязательными валидаторами × 3 итерации фиксов сжигают 600к токенов только на спеку фичи — до того как написана первая строка кода.

2. **Cadence tiering.** `cadence-first` выбирает Tier 1/2/3 на блок. Тривиальные фиксы идут Plan-only (~$0.15). Sibling-mirror UI-изменения идут Library+Plan (~$0.60). Сложные рефакторинги идут по полной цепочке (~$1-2). Ты платишь пропорционально сложности, а не за overhead одного heavy pipeline для всего.

3. **Artifact-first как кэш.** Возвращаешься к задаче через две недели? Читаешь `report-N.md` (2-3к токенов) вместо перезагрузки полного контекста (30-50к токенов). Экономия 15-25x на возврате в контекст.

Полная аргументация в [Почему artifact-first § Скиллы, не агенты](./README.ru.md#скиллы-не-агенты).

## Почему нет агентов как в других фреймворках?

Skills-first — осознанный архитектурный выбор, а не пропущенная фича:

- **Стоимость задачи падает в 5-10 раз** (скиллы переиспользуют основной контекст, никакой per-validator subagent-загрузки)
- **Всё дебажится** — tool calls, edit'ы, проверки видны в чате
- **Проще онбординг** — одна абстракция (скиллы), а не две (скиллы + агенты)
- **Right-sized cadence** — Tier 1/2/3 на блок вместо одного heavy pipeline для 1-line изменения цвета кнопки

Точечные агенты (research, parallel audit, security scan) в roadmap как **opt-in power tools** для тех 10% работы, где реально нужен параллелизм или изоляция контекста. Не как обязательный overhead на каждую задачу. Ты платишь за agent-возможности только когда сам их вызываешь.

## Работает на Windows?

Unix-first. Скрипты в `bin/` предполагают `bash 3.2+`, `sqlite3`, `python3`. WSL должен работать, но end-to-end не тестировали. Windows-native поддержка не в scope сейчас — patches welcome.

## С какими AI-моделями работает?

Поставляемые скиллы написаны под Claude (используют паттерн `Skill('name')` из Claude Code и Claude Agent SDK). Сам artifact-контракт language-agnostic — любой агент, который умеет вызывать скиллы по имени и читать/писать markdown, может им пользоваться. Адаптация под других провайдеров = переименование invocation shape; дисциплина переносится.

## Можно ли использовать без Claude Code?

Да — artifact-контракт (создать файл + вставить строку в routing.db) — вот что важно, а не invocation harness. Можешь использовать Claude Agent SDK, raw API-запросы или другой agent-фреймворк, если твой агент соблюдает правило «один шаг = один файл» и пишет в ту же routing.db schema. Flow UI работает над любой заполненной routing.db независимо от того, кто её заполнил.

## Как обновить скиллы?

```bash
bash bin/sync-from-aihub.sh
```

Тянет из upstream aihub-источника. Настрой upstream-путь в `framework.yml` (по умолчанию: bundled `./aihub`). Sync пишет per-run лог в `.sync-log/` для аудита. Diff'ы конкретных скиллов приземляются в `aihub/.claude/skills/{name}/SKILL.md`.

## Как написать свой скилл?

Следуй [`docs/SKILL_CONTRACT.md`](./docs/SKILL_CONTRACT.md) — обязательные frontmatter-поля, три body-секции (Input / Output / Hands off to), проверки линтера. Затем зарегистрируй в `manifest.yml` и запусти `bash bin/verify-contract.sh` для проверки соответствия. Полный флоу в [`CONTRIBUTING.md`](./CONTRIBUTING.md#adding-a-skill).

## Какие commit-конвенции?

Лёгкая конвенция: `<prefix>: <short summary>`, где prefix — один из `feat / fix / docs / refactor / chore / test`. Body опциональный, wrap на 72 столбцах. Ссылайся на issues через `Closes #NN`. Детали в [`CONTRIBUTING.md#commit-messages`](./CONTRIBUTING.md#commit-messages).

## Что в roadmap?

Post-launch приоритеты примерно по порядку:

1. **CI polish** — GitHub Actions workflow, drift detection, PR gating.
2. **Skill authoring UX** — scaffolding-тула, которая генерирует compliant
   `SKILL.md` skeleton из короткого опросника.
3. **Flow UI improvements** — лучший поиск по артефактам, cross-project
   фильтрация, экспорт графиков.
4. **Multi-provider skill invocation** — тонкий адаптер, чтобы те же
   скиллы работали под Claude Agent SDK / raw API / другими harness'ами.
5. **Non-Claude examples** — sample-скиллы, показывающие как artifact-контракт
   держится под другой моделью.

Мнение сообщества помогает выбрать приоритеты — открывай [Discussion](../../discussions) в категории Ideas.
